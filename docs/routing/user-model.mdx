# User Model
---

## Overview

Up to this point, reviews have no author — any user can write any number of reviews, and there is no record of *who* wrote what. This lecture adds a `ForeignKey` to Django's built-in `User` model on the `Review` model, updates the serializer to expose the username, and implements a guard in `perform_create` to prevent a user from reviewing the same movie more than once.

---

## The Problems Being Solved

| Problem | Solution |
|---|---|
| No author tracked on reviews | Add `ForeignKey` to `User` |
| Anyone can submit unlimited reviews for the same movie | Check for existing review in `perform_create` |
| Anyone can edit any review without being logged in | Covered in the next lecture (Permissions) |

---

## Step 1 — Update the Review Model

```python
# models.py
from django.contrib.auth.models import User

class Review(models.Model):
    review_user = models.ForeignKey(
        User,
        on_delete=models.CASCADE
    )
    rating = models.PositiveIntegerField()
    description = models.CharField(max_length=200, null=True)
    watchlist = models.ForeignKey(WatchList, on_delete=models.CASCADE, related_name='reviews')
    active = models.BooleanField(default=True)
    created = models.DateTimeField(auto_now_add=True)
    update = models.DateTimeField(auto_now=True)

    def __str__(self):
        return f"{self.rating} | {self.watchlist.title}"
```

> **Before migrating:** Delete all existing reviews from the admin panel. Since the new `review_user` field is non-nullable, old rows with no user would fail the migration.

## Step 3 — Update the Serializer

Add `review_user` as a **read-only** `StringRelatedField` so the username is shown in responses but is not required in the request body:

```python
# serializers.py
class ReviewSerializer(serializers.ModelSerializer):
    review_user = serializers.StringRelatedField(read_only=True)

    class Meta:
        model = Review
        exclude = ('watchlist',)
```

`StringRelatedField` calls `__str__()` on the related object — for `User`, this returns the **username**.

---

## Step 4 — Auto-Assign User in perform_create

Pass the currently authenticated user when saving a new review:

```python
# views.py
class ReviewCreate(generics.CreateAPIView):
    serializer_class = ReviewSerializer

    def get_queryset(self):
        return Review.objects.all()

    def perform_create(self, serializer):
        pk = self.kwargs['pk']
        movie = WatchList.objects.get(pk=pk)

        review_user = self.request.user
        serializer.save(watchlist=movie, review_user=review_user)
```

### Flow

```
POST /stream/1/review-create/
        ↓
perform_create(serializer)
        ↓
pk = 1 → WatchList.objects.get(pk=1) → movie
        ↓
review_user = request.user → "shubham"
        ↓
serializer.save(watchlist=movie, review_user=review_user)
        ↓
Review saved with both FK fields set automatically
```

## Step 5 — Prevent Duplicate Reviews

Before saving, check if the current user has already reviewed this movie. If so, raise a `ValidationError`:

```python
# views.py
from rest_framework.exceptions import ValidationError

class ReviewCreate(generics.CreateAPIView):
    serializer_class = ReviewSerializer

    def get_queryset(self):
        return Review.objects.all()

    def perform_create(self, serializer):
        pk = self.kwargs['pk']
        movie = WatchList.objects.get(pk=pk)
        review_user = self.request.user

        # Check for existing review by this user for this movie
        review_qs = Review.objects.filter(
            watchlist=movie,
            review_user=review_user
        )

        if review_qs.exists():
            raise ValidationError("You have already reviewed this movie.")

        serializer.save(watchlist=movie, review_user=review_user)
```

### Result

```json
// Attempting a second review returns:
{
    "non_field_errors": [
        "You have already reviewed this movie."
    ]
}
```

## Key Takeaway

> Adding `review_user = ForeignKey(User)` ties reviews to accounts. Overriding `perform_create` injects both the movie and the user automatically — keeping the API clean (no FK fields in the request body). The `ValidationError` guard enforces one-review-per-user-per-movie at the API layer before anything hits the database.
