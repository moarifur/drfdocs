# API

## What is an API?

**API** stands for **Application Programming Interface**. In simple terms, an API acts as a **middleman** between two different applications, enabling them to talk to each other.

> Think of it like a waiter in a restaurant. You (the client) place an order, the waiter (the API) takes it to the kitchen (the server), and then brings the food (the response) back to you.

## Real-World Example

**Uber** uses **Google Maps** for navigation. These are two separate products, but they are connected through an API. The API acts as the bridge between the two systems.

APIs are also used within a single organization — for example, connecting a website and a mobile app to the same backend using a shared API.

## Types of APIs

### 1. Private API
Used **within an organization only**. No external third party can access it. Example: A company with a website, iOS app, Android app, and desktop application all sharing one backend through a private API.

### 2. Partner API
Designed for **specific business partners**. Not publicly available — organizations must apply, get approved, and agree on terms before gaining access. Example: IMDB's API used by Amazon Prime Video.

### 3. Public API
**Open to anyone** who registers. Some have free tiers, others have paid plans for heavy usage. Examples: OpenWeatherMap API (weather data), CoinMarketCap API (cryptocurrency data).

## Communication Format

APIs communicate using a standard data format. The most common is **JSON** (JavaScript Object Notation). XML is an alternative, but JSON is preferred for its simplicity.

```json
{
  "username": "john",
  "email": "john@example.com",
  "token": "abc123xyz"
}
```

## Consumers vs. Providers

| Role | Description |
|------|-------------|
| **Consumer** | An application that fetches data from another API |
| **Provider** | An application that creates and exposes an API for others to use |

The goal of this course is to teach you how to **become a provider** — building APIs with Django REST Framework that other applications (web, iOS, Android) can consume.

## URL Structure

APIs use structured URLs called **endpoints**:

- **Base URL**: The common part shared across all endpoints (e.g., `https://api.example.com`)
- **Endpoint**: The specific path for a resource (e.g., `/movies/` or `/movies/127/`)

```
https://api.example.com/movies/          → List of all movies
https://api.example.com/movies/127/      → Individual movie (ID: 127)
https://api.example.com/movies/127/reviews/?limit=20  → Reviews with limit
```
