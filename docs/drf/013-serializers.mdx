# Serializers
---

## Goal

Implement a `GET` endpoint using DRF serializers and function-based views.

---

## Step 1: Create the Serializer

In `watchlist_app/api/serializers.py`:

```python
from rest_framework import serializers

class MovieSerializer(serializers.Serializer):
    id          = serializers.IntegerField(read_only=True)
    name        = serializers.CharField()
    description = serializers.CharField()
    active      = serializers.BooleanField()
```

| Field | Type | Notes |
|---|---|---|
| `id` | `IntegerField` | `read_only=True` — auto-generated, not editable |
| `name` | `CharField` | Required, readable and writable |
| `description` | `CharField` | Required |
| `active` | `BooleanField` | Required |

---

## Step 2: Create the Views

In `watchlist_app/api/views.py`:

```python
from rest_framework.decorators import api_view
from rest_framework.response import Response
from watchlist_app.models import Movie
from watchlist_app.api.serializers import MovieSerializer

@api_view(['GET'])
def movie_list(request):
    movies = Movie.objects.all()
    serializer = MovieSerializer(movies, many=True)  # many=True for QuerySet
    return Response(serializer.data)

@api_view(['GET'])
def movie_detail(request, pk):
    movie = Movie.objects.get(pk=pk)
    serializer = MovieSerializer(movie)              # single object, no many=True
    return Response(serializer.data)
```

### `many=True` — When to Use It

| Scenario | `many=` |
|---|---|
| Serializing a **list** (QuerySet) | `many=True` |
| Serializing a **single object** | (omit / default `False`) |

## Step 3: Wire Up URLs

In `watchlist_app/api/urls.py`:

```python
from django.urls import path
from watchlist_app.api.views import movie_list, movie_detail

urlpatterns = [
    path('list/',     movie_list,   name='movie-list'),
    path('<int:pk>/', movie_detail, name='movie-detail'),
]
```

In `watchmate/urls.py`:

```python
from django.urls import path, include

urlpatterns = [
    path('watch/', include('watchlist_app.api.urls')),
]
```

## The `@api_view` Decorator

The `@api_view` decorator specifies which HTTP methods the view accepts:

```python
@api_view(['GET'])           # Only GET
@api_view(['GET', 'POST'])   # GET and POST
```

Without this decorator, DRF raises: `accepted_formats not set on Response`.

---

## DRF Browsable API

When you visit the endpoint in a browser, DRF renders a visual interface showing:

- **Status Code** (e.g., `200 OK`)
- **Allowed Methods** (e.g., `GET`)
- **Response Data** (formatted JSON)
- **POST Form** (if POST is included in `@api_view`)

```
GET http://127.0.0.1:8000/watch/list/
```

## Before vs After DRF

| Old Approach | DRF Approach |
|---|---|
| `Movie.objects.all().values()` → `list()` → `JsonResponse` | `MovieSerializer(movies, many=True).data` → `Response` |
| Manual field mapping in view | Serializer handles all field mapping |
| No validation | Built-in `.is_valid()` |
