# Pagination

## Overview

Pagination splits large result sets into multiple pages. Instead of loading all 1,000 items in one response, each request returns a controlled slice (e.g. 10 items), along with links to the next and previous pages.

---

## Why Pagination Matters

- **Reduces API load** — only the requested slice is fetched from the database
- **Reduces client load** — the browser/app renders fewer items
- **Improves UX** — users naturally navigate page by page

On Amazon: searching "laptop" with thousands of results — only 10–20 items are loaded per page click.

---

## Pagination Types in DRF

| Type | Description |
|------|-------------|
| `PageNumberPagination` | Standard page numbers (`?page=2`) |
| `LimitOffsetPagination` | Explicit limit and offset (`?limit=10&offset=20`) |
| `CursorPagination` | Opaque cursor, no random access (`?cursor=abc123`) |

---

## Setting Up `PageNumberPagination`

Create a dedicated `pagination.py` file inside your app:

```python
# watchlist_app/api/pagination.py
from rest_framework.pagination import PageNumberPagination

class WatchListPagination(PageNumberPagination):
    page_size = 7                     # items per page
    page_size_query_param = 'size'    # client can override: ?size=10
    max_page_size = 10                # ceiling for client-requested size
    page_query_param = 'page'         # URL param for page number: ?page=2
```

Import and apply it on your view:

```python
# views.py
from watchlist_app.api.pagination import WatchListPagination

class WatchListGV(generics.ListAPIView):
    queryset = WatchList.objects.all()
    serializer_class = WatchListSerializer
    pagination_class = WatchListPagination
```

## Response Structure

```json
{
  "count": 17,
  "next": "http://localhost:8000/watch/list/?page=2",
  "previous": null,
  "results": [
    { "id": 1, "title": "Movie 1", ... },
    ...
  ]
}
```

| Field | Description |
|-------|-------------|
| `count` | Total number of items across all pages |
| `next` | URL of the next page (`null` on last page) |
| `previous` | URL of the previous page (`null` on first page) |
| `results` | The items for the current page |

---

## Pagination Attributes Reference

| Attribute | Purpose | Example |
|-----------|---------|---------|
| `page_size` | Default items per page | `page_size = 7` |
| `page_query_param` | Name of the page number URL param | `page_query_param = 'page'` |
| `page_size_query_param` | Allows client to set their own page size | `page_size_query_param = 'size'` |
| `max_page_size` | Maximum allowed client-requested size | `max_page_size = 10` |
| `last_page_strings` | String that jumps to the last page | `last_page_strings = ('last',)` |

---

## Client-Controlled Page Size

When `page_size_query_param` is set, the client can override the page size per request:

```
GET /watch/list/?size=10        # load 10 items per page
GET /watch/list/?size=20        # load 20 (capped at max_page_size)
GET /watch/list/?size=1000      # still capped at max_page_size
```

> This mirrors **CoinMarketCap**, which lets users choose 24, 50, or 100 coins per page.

---

## Jumping to the Last Page

```python
last_page_strings = ('last',)
```

```
GET /watch/list/?page=last      # returns the final page of results
```

---

## Customising the Page Parameter Name

You can rename the `?page=` parameter to anything:

```python
page_query_param = 'p'
# Now use: ?p=2, ?p=3
```

---

## Global vs Local Pagination

| Level | How | Applies To |
|-------|-----|-----------|
| Global | Add `DEFAULT_PAGINATION_CLASS` + `PAGE_SIZE` to `REST_FRAMEWORK` in `settings.py` | All views |
| Local | Set `pagination_class` on individual view | That view only |

Prefer **local pagination** for fine-grained control. The global setting is a useful fallback but forces pagination on views that may not need it.

---

## Key Takeaway

`PageNumberPagination` is the most intuitive pagination style — clients navigate by page number. Use `page_size_query_param` to give clients flexibility, and `max_page_size` to prevent abuse. Always apply pagination locally (`pagination_class` on the view) unless you truly need it everywhere.
